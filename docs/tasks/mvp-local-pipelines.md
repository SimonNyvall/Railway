# Handoff: Railway MVP — local pipelines CLI

Status: **implemented** — MVP shipped (WS0–WS6); core logic subsequently
extracted to `Engine/` (see `docs/tasks/engine-extraction.md`, steps 0–9 complete).

## Goal

Ship the MVP of `railway`, a git-like CLI that runs local CI pipelines defined in
YAML inside a repository's `.railway/` folder. Commands must be flat (git-style),
repo-scoped, and usable by both humans and agents (MCP later).

## MVP scope (from README, revised)

- [ ] List pipelines (current repo only)
- [x] Validate a pipeline yaml (already implemented, keep behavior)
- [ ] Manually trigger a pipeline (live-streamed, run at repo root)
- [ ] Show a dashboard of the repo's pipelines, validation state, and runs
- [ ] Persist run history

**Dropped from MVP:** "link pipeline to a repo" (old concept, removed) and the
"one pipeline → many repos" model. README MVP list must be updated to match.

## Assumptions to confirm before/at implementation

1. **Repo resolution vs Q5.** User answered "yes" to `run` working outside the
   repo, but also "list = current repo only" and removed linking. Without a
   registry there is nothing to resolve from outside. **Assumed: repo-scoped** —
   every command discovers `.railway` by walking up from cwd (git-style). The DB
   stores only run history + a `Repository` row per repo ran. If cross-repo
   resolution is actually required, this must be revisited (add an auto-populated
   registry).
2. **`railway.yaml` shape** (Q1a/1c unanswered). Assumed CLI-maintained manifest:
   - `pipelines/*.yaml` remain the **source of truth**.
   - `railway.yaml` holds repo metadata and an optional `pipelines:` index
     (`name`, `path`), regenerated by the CLI. Hand-editing tolerated; missing /
     extra entries are reconciled on read. If you want a different shape, say so.
3. **Job execution** (Q10 remainder). Assumed: honor `depends_on` ordering
   (topological), execute **sequentially** (not parallel), **stop on first
   failure**. Parallelism, `continue-on-error`, `locks`, and `Timeout`
   enforcement are **out of scope** for MVP (parsed but ignored).
4. **Shell** (Q11 remainder). Assumed platform default: `sh -c` (Unix),
   `cmd /c` (Windows). Env merge order: process env → `pipeline.variables` →
   `job.env` → `step.env` (later wins).
5. **Run selection.** `run` takes the file name (e.g. `railway run build.yaml`);
   duplicate file names in nested dirs → fatal listing candidates.
6. **Run history view.** Persist runs and show recent runs in the dashboard.
   A dedicated `railway runs` command is a stretch item, not required.
7. **Testability.** Handlers currently `new` themselves through `LifetimeService`.
   To make FakeItEasy-based unit tests possible, add interface-accepting
   constructor overloads while keeping the parameterless ctor for the locator.

## CLI UX specification

Binary `railway`, version `0.0.1`.

Common: any command requires a `.railway` folder reachable by walking up from cwd.
If absent → print `fatal: not a railway repository (or any parent): .railway` +
`hint: run 'railway init'` and exit `1`. Never auto-init.

### `railway init`
- Fatal if not in a git repo (`fatal: not a git repository ...`), exit 1.
- Creates `.railway/`, `.railway/pipelines/`, `.railway/railway.yaml`.
- Idempotent: "Reinitialized existing Railway repository in <path>".

### `railway validate <path>`
- Unchanged from today. Path argument required; `.yml`/`.yaml` only.
- Exit 0 valid, 1 invalid / not a yaml / missing path.

### `railway list`
- Scans `.railway/pipelines/**/*.{yml,yaml}` in the current repo.
- One entry per file: `"<file-name> - name: <inside-name>"`.
- Invalid/unparseable files shown flagged, still listed.
- Exit 0; fatal (see common) if no `.railway`.

### `railway run <file-name>`
- Resolves the pipeline file by name under `.railway/pipelines/`.
- Auto-validates first; invalid → fatal, exit 1.
- Runs at repo root cwd, jobs honored via `depends_on` (sequential), stop on first
  failure, live-stream stdout/stderr with a per-step banner.
- Persists a run (job/step status, output, timestamps, exit code).
- Exit 0 on success, 1 on any failure; `--verbose` prints detailed errors.

### `railway` (default) — Dashboard
- Shows repo name, configured pipelines with validation state, and recent runs.

## Data model changes

- Keep `Pipeline`, `Repository`, `RepositoryPipeline` entities ("keep as is").
  `RepositoryPipeline` stays unused in MVP.
- `Pipeline.Jobs` / `Variables` remain `Ignore`d.
- Add run-history tables:
  - `Run` { Id, RepositoryId, PipelineFileName, PipelineName, StartedAt,
    FinishedAt, Status, ExitCode }
  - `RunJob` { Id, RunId, Name, Status, StartedAt, FinishedAt, ExitCode }
  - `RunStep` { Id, RunJobId, Name, Command, Status, StartedAt, FinishedAt,
    ExitCode, Output }
- Status enum: `Succeeded` / `Failed` (later: `Running`, `Cancelled`).
- Populate `Repository` on run (lookup/create by path).

## WS0 review findings

Reviewed: unstaged WS0 changes (fixed point `6a08cc4`).

- **Duplicated Code (fixed).** `GetRootRepositoryPath` and `GetRailwayPath`
  repeated the same walk-up-the-tree search. Extracted `FindUpwards(predicate)`.
- **Dangerous enum default (open).** `RunStatus` declares `Succeeded = 0`, so an
  uninitialized `Run`/`RunJob`/`RunStep` serializes as `Succeeded`. Suggest
  `Succeeded = 1` with an explicit `Unknown = 0`, or document that WS4 must always
  set status before persisting. Left as-is to match the agreed enum shape.
- **Missing XML docs (open).** New public interfaces (`IListHandler`, `IRunHandler`,
  `IPipelineDiscoveryService`, `IRunnerService`, `IDashboardService`) and public
  domain types carry no XML comments. Repo convention is currently undocumented, so
  this is a consistency decision: document interfaces (per `/csharp-docs`) and use
  `<inheritdoc/>` on implementations, or keep the existing no-docs convention.
- **Broad catch (open).** `PipelineHelper.TryParse` catches `Exception`; a bug in
  deserialization is reported as "invalid pipeline". Narrow to
  `YamlException`/`IOException`/`FormatException`.
- **Duplicated constants (WS1).** `InitHandler` still hardcodes `.railway`,
  `railway.yaml`, and `pipelines`; `RepositoryHelper` now exposes constants for
  them. WS1 should consume the constants.
- **Intentional scaffolding.** `ListHandler`, `RunHandler`, and the three service
  shells throw `NotImplementedException`; WS3/WS4/WS5 replace the bodies. Commands
  swallow exceptions and return `1`, so no fatal/hint output is wired yet — that
  lands with the common gating work.
- **Minor naming.** Domain type `Run` overlaps `IRunnerService.Run(...)`.
